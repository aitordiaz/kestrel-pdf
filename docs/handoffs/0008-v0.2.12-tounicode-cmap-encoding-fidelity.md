## 1. Executive Summary

This engineering session resolved critical font encoding and character decoding fidelity issues ("caracteres raros") where Spanish and Western European text in subsetted TrueType/Type1 PDF documents rendered as corrupted foreign scripts (e.g. Arabic or Indic characters). 

We implemented a robust, universal `ToUnicodeCMap` decoding engine supporting 1-byte, 2-byte, and mixed codespaces, indirect `/Encoding` reference resolution, `/DescendantFonts` CMap discovery, and seamless Latin-1 / Windows-1252 accented character preservation. All behaviors were developed and validated via strict Spec-Driven Development (SDD) and Test-Driven Development (TDD) using pure in-memory synthetic PDF generation with zero external files or PII.

---

## 2. Key Accomplishments & Changes

1. **Root Cause Analysis & Architecture Redesign**:
   - Diagnosed that subsetted simple fonts (TrueType, Type 1) declare 1-byte code spaces (`begincodespacerange <00> <FF> endcodespacerange`), yet operands in `TJ` group single-byte character codes into tokens (e.g., `<0607>` representing two distinct 1-byte character codes `0x06` and `0x07`).
   - The engine previously assumed all ToUnicode CMaps operated strictly on 2-byte chunks (`bytes.chunks(2)`), constructing invalid 16-bit IDs (e.g., `0x0607 = 1543`) which failed lookup and fell back to `char::from_u32(1543)` emitting Arabic character `؇`.
   - Redesigned `ToUnicodeCMap` struct in [`crates/kestrel-core/src/document.rs`](file:///home/aitor/projects/kestrel-pdf/crates/kestrel-core/src/document.rs) to track `code_bytes` (1 or 2) and explicit `codespace_ranges` `(start, end, byte_len)`.

2. **Universal Variable-Width CMap Byte Decoder**:
   - Implemented `ToUnicodeCMap::decode_bytes(&self, bytes: &[u8], output: &mut String)`.
   - Accurately consumes 1 byte per character code for 1-byte codespaces and 2 bytes per character code for 2-byte Identity-H codespaces.
   - Replaced arbitrary glyph ID fallbacks: unmapped codes never emit arbitrary Unicode codepoints outside printable ASCII (`32..=126`), eliminating script leakage.

3. **Indirect `/Encoding` Resolution & Accented Fallback**:
   - Dereferenced indirect `Object::Reference` font `/Encoding` objects.
   - Extracted `/BaseEncoding` when `/Encoding` is a dictionary.
   - Traversed `/DescendantFonts` in Type 0 composite fonts to locate descendant `/ToUnicode` streams.
   - Preserved Windows-1252 / ISO-8859-1 accented characters (`0xA0..=0xFF`, such as `á, é, í, ó, ú, ñ, ¿, ¡, €`) for single-byte fonts without CMaps.

4. **TDD Synthetic Tests**:
   - Added `test_integration_single_byte_tounicode_cmap_extraction` in [`crates/kestrel-core/tests/integration_tests.rs`](file:///home/aitor/projects/kestrel-pdf/crates/kestrel-core/tests/integration_tests.rs) exercising 1-byte ToUnicode CMaps with multi-byte hex tokens.
   - Added `test_integration_winansi_accented_characters_without_cmap` verifying unmapped single-byte strings preserve Spanish accented characters.
   - All tests synthesize clean PDF 1.7 documents directly in RAM with zero disk I/O, zero file tracking, and zero PII.
