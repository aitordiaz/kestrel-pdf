## 1. Objective & Scope

### 1.1 Problem Statement
Certain PDF documents (such as administrative notifications, reports generated by LibreOffice, ReportLab, or government portals) exhibit corrupted text rendering ("caracteres raros"). For example, Spanish words like "Ayuntamiento" render as `Ayunt؇iऄto` with unexpected Arabic or Devanagari characters.

Root-cause investigation reveals:
1. **Hardcoded 2-Byte Assumption in ToUnicode CMap Decoding**:
   The parser previously assumed all ToUnicode CMaps operate on 2-byte (`u16`) character codes (`bytes.chunks(2)`).
   However, subsetted Simple Fonts (`/Subtype /TrueType` or `/Subtype /Type1`) use **1-byte character codes** (`0x00..=0xFF`) with 1-byte code spaces (`begincodespacerange <00> <FF> endcodespacerange`).
   When content streams concatenate 1-byte character codes (e.g. `<0607>` for `'a'` and `'m'`), chunking by 2 bytes formed `0x0607` (1543), which failed CMap lookup and erroneously decoded via `char::from_u32(1543)` as Arabic sign `؇`.
2. **Unmapped Glyph Fallback Pollution**:
   When a 2-byte chunk failed CMap lookup, the engine blindly cast arbitrary glyph index IDs to Unicode codepoints (`char::from_u32(code)`), turning arbitrary font internal indices into foreign scripts (Arabic, Cyrillic, Indic).
3. **Indirect and Dictionary `/Encoding` Object Unwrapping**:
   Font dictionaries referencing indirect `/Encoding` objects (`Object::Reference`) or dictionaries with `/BaseEncoding` were ignored by `font_dict.get(b"Encoding").and_then(Object::as_name_str)`.
4. **Western European / Windows-1252 Accented Byte Preservation**:
   Unmapped single-byte strings containing Latin-1 / Windows-1252 characters (e.g. `0xF3` for `ó`, `0xF1` for `ñ`) were filtered out by `(32..=126)` ASCII ranges.

### 1.2 Target Capabilities
1. **Dynamic Code-Length CMap Engine (`ToUnicodeCMap`)**:
   - Detect codespace byte width from `begincodespacerange` (e.g. `<00> <FF>` is 1-byte, `<0000> <FFFF>` is 2-byte).
   - Support mixed 1-byte and 2-byte codespaces according to Adobe CMap specification.
   - Fall back gracefully to `src_hex` token lengths in `bfchar` / `bfrange`.
2. **Safe Fallback for Unmapped Glyphs**:
   - Never convert arbitrary glyph index numbers into unicode characters unless verified as standard printable ASCII or mapped via CMap.
3. **Indirect Reference & Dictionary `/Encoding` Resolution**:
   - Dereference `Object::Reference` for font `/Encoding` objects.
   - Extract `/BaseEncoding` from `/Encoding` dictionaries.
   - Follow `/DescendantFonts` to discover descendant `/ToUnicode` CMaps.
4. **Complete ISO-8859-1 / Windows-1252 Accented Text Fallback**:
   - Preserve all accented characters (`á, é, í, ó, ú, ñ, ¿, ¡, €`) in single-byte text streams.
5. **Strict Data Privacy & Synthetic Testing**:
   - Strictly 0 binary PDF files committed to disk or git.
   - Zero hardcoded local filesystem paths or user/institution PII.
   - 100% reproducible synthetic in-memory PDF generation.

## 2. Technical Specification

### 2.1 Data Structure & Parser (`crates/kestrel-core/src/document.rs`)

```rust
#[derive(Debug, Clone, Default, PartialEq)]
pub struct ToUnicodeCMap {
    /// Mapping from character code to decoded Unicode string.
    pub map: std::collections::HashMap<u16, String>,
    /// Default byte length per character code (1 or 2).
    pub code_bytes: usize,
    /// Explicit codespace ranges (start, end, byte_len) parsed from begincodespacerange.
    pub codespace_ranges: Vec<(u32, u32, usize)>,
}

impl ToUnicodeCMap {
    /// Decodes a raw byte slice from a content stream string operand into the output buffer.
    pub fn decode_bytes(&self, bytes: &[u8], output: &mut String);
}
```

### 2.2 Content Stream String Decoder

- If font has `ToUnicodeCMap`:
  - Process bytes using codespace ranges and `code_bytes`.
  - For 1-byte codes (`<01>`, `<0607>`), consume 1 byte per character code and lookup in CMap.
  - For 2-byte codes (`<00010002>`), consume 2 bytes per character code and lookup in CMap.
- If font does NOT have `ToUnicodeCMap`:
  - Check `/Encoding` (Identity-H, WinAnsiEncoding, StandardEncoding).
  - Resolve indirect `/Encoding` references and dictionary `/BaseEncoding`.
  - Decode Windows-1252 / ISO-8859-1 for bytes in `0x80..=0xFF`.
